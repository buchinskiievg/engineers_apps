# #005 Engineering Document Studio — как устроен DWG-движок и страница

Доко-файл модуля `lab/document-studio/`. Страница собирает из DWG / PDF / картинок один PDF
в браузере. Файлы на сервер не уходят; исключение — Word, который идёт на конвертацию в
`api.ieccalc.com`. `ARCHITECTURE.md` рядом — старое описание замысла, по коду не актуально.

## Файлы

| файл | что делает |
|------|------------|
| `index.html` | страница: панель инструментов с дроп-зоной, три колонки (файлы → листы → превью), лента страниц PDF, экспорт |
| `libredwg-engine.js` | DWG → SVG-листы: `parseDwg(file)`, `svgToPng(svg)`, `sheetsPdf(layouts)` |
| `dwg-render.js` | свой рендерер сущностей DWG → SVG (r2) |
| `canvas-view.js` | превью листа на canvas: `compile(svg)` → сцена, `draw(ctx, scene, view, …)` (r2e) |
| `fonts/` | встроенные шрифты (Arimo, Tinos, Cousine, osifont, URW Gothic) + LICENSES.txt |
| `libredwg-web.wasm` | не в git; лежит в staging-копии прода и выкладывается вместе с папкой |

Импорты в `index.html` идут с ключом кэша `?v=…` (сейчас движок `r2f`, canvas-view `r2f`).
**Любая правка файла — бампать его ключ.**

## Модель данных libredwg-web 0.7.14 (то, что читает движок)

- Пространства: `db.tables.BLOCK_RECORD.entries`, `*Model_Space` / `*Paper_Space*`. Регистр в
  именах бывает любой: встречается `*MODEL_SPACE`.
- Объекты: `db.entities` — плоский список, у каждого `ownerBlockRecordSoftId`.
- Листы: `db.objects.LAYOUT` — `layoutName`, `tabOrder`, `minLimit/maxLimit` (лист бумаги),
  `viewportId` (handle собственного VP листа).
- Слои: `db.tables.LAYER.entries` — `frozen`, `off`, `plotFlag` (0 значит «не печатать»;
  у `Defpoints` всегда 0).
- VIEWPORT:
  - `viewportCenter`, `width`, `height` — на бумаге;
  - `targetPoint + displayCenter` — центр вида в модели;
  - `viewHeight` — высота вида в модели;
  - `viewTwistAngle` — поворот, радианы;
  - `statusBitFlags & 0x20000` — VP выключен;
  - `viewportId === 1` — сам лист.
- `frozenLayerIds` не заполняется, поэтому заморозку слоёв по видовым экранам сделать нельзя.

## Как рисуется DWG (`parseDwg`)

1. На каждый файл создаётся свой экземпляр `LibreDwg.create()`. Общий экземпляр ломается на
   втором чтении («null function» → Aborted). WASM отдаётся с ETag, так что повторная загрузка
   стоит около 0,5 с.
2. **Слои.** Объекты на слоях off / frozen / no-plot в лист не идут: `layerFilter`.
3. **Изоляция пространства.** `dwg_to_svg` рисует все блок-записи сразу, включая чужие
   пространства. `isolate()` опустошает остальные Model/Paper записи и оставляет только свои
   объекты.
4. **Модель рисуется один раз.** Она служит и отдельным листом «Model», и содержимым всех
   видовых экранов.
5. **Лист = бумага + окна в модель (`composeSheet`).** Paper space сам по себе — это штамп,
   рамки и прямоугольники VP, а внутри VP пусто. Лист из одних видовых экранов поэтому выходил
   пустым: так и было у пользователя, 23.09.2026. Для каждого VP модель вставляется
   клипованной группой:
   ```
   M = targetPoint + displayCenter,  s = height / viewHeight,  C = viewportCenter
   translate(Cx, −Cy) scale(s) rotate(twist°) translate(−Mx, My)
   ```
   Модель кладётся под графику бумаги, чтобы штамп лежал сверху. Id модели получают префикс
   `dsN-`: `<use>` берёт первый элемент с id, а в листе под теми же id лежат опустошённые копии.
6. **Рамка листа (`sheetExtents`).** Сначала лимиты LAYOUT (лист бумаги). Если их нет —
   extents листа. Если нет и их — объекты + прямоугольники VP.
7. **Рамка модели.** Пересечение двух коробок:
   - робастной по точкам (0,5–99,5 перцентиль; EXTMIN/EXTMAX из заголовка берутся, только если
     внутри ≥90 % точек и заголовок не больше 3× робастной);
   - реально нарисованной (`drawnBox`: `getBBox()` в скрытом DOM).

   Одних точек мало: INSERT считается по точке вставки, и блок с базой в начале координат
   растягивал рамку. C107 шириной 80 единиц выходил в рамке 1 300, с чертежом-точкой в углу.
8. Листы, в которых нечего показать, помечаются `empty`. Если все листы пустые, а модель нет
   (`modelOnly`), модель включается сама.

### Очистка SVG от LibreDWG

- **Экранирование текста (`xmlSafe`).** Текст чертежа пишется как есть: «Bopp & Reuther»,
  «R<=2 Ohm». Это невалидный XML. Инлайн в странице он прощается, а в `<img>` не грузится. Все
  миниатюры и растр для PDF были пустыми практически на любом реальном чертеже. Движок
  экранирует содержимое `<text>` (`<tspan>` библиотека не пишет) и голые `&`, выбрасывает
  запрещённые управляющие символы.
- **Цвет 7 (`onPaper`).** LibreDWG пишет его белым, AutoCAD печатает чёрным. Белый заменяется
  на чёрный — это второй по частоте цвет на всех тестовых чертежах.
- **Корень `<svg>` пересобирается (`frame`).** Второй `preserveAspectRatio` или `width` тоже
  делает XML невалидным.
- **ACAD_TABLE роняет `dwg_to_svg`** («topBorderVisibility»). `drawSvg` повторяет отрисовку без
  таблиц и сообщает, сколько пропущено.

## Навигатор «Files & pages» (переделан 23.09.2026)

Одна колонка вместо трёх панелей: файлы, миниатюры и нижней ленты «Output PDF» больше нет.

- **Документ** — это то, что станет одним PDF. Модель: `state.docs[]` вида
  `{id, name, sourceIds, all, pages, open, merged}`:
  - `all` — все страницы, которые документ может содержать, в исходном порядке;
  - `pages` — сам PDF, в его порядке.
- **Страница** принадлежит документу (`p.docId`). Страницы, не вошедшие в PDF (убранные,
  пустые листы, Model), лежат в секции «NOT IN THE PDF» и возвращаются кнопкой «+» на своё
  место.
- **Строка файла.** Кнопка `+`/`−` раскрывает сетку страниц; справа RELOAD (для DWG), ✕ и
  **⤓ PDF**, то есть скачать этот документ.
- **Объединение.** Строку файла тянут на середину другой строки, открывается окно «Merge
  files». В нём порядок задаётся стрелками, имя идёт за порядком, пока его не ввели вручную.
  Результат — **новая** строка после исходных:
  - исходные файлы остаются;
  - у объединённого свои копии страниц (`orig` ссылается на оригинал, миниатюра и растр общие),
    поэтому поворот и удаление в нём исходники не трогают.
  - Если бросить строку на верхнюю или нижнюю четверть другой строки, файлы просто меняются
    местами.
- **Перетаскивание страниц** сделано на pointer-событиях, без HTML5 DnD: нативный drag
  `<img>` отдавал странице файл «download.svg», и зона «брось куда угодно» открывала его как
  новый источник. Страница-карточка сама становится слотом вставки (пунктирная красная рамка),
  копия едет за курсором, соседи плавно сдвигаются (FLIP-анимация). У краёв колонка
  автопрокручивается. Выделенная группа (Ctrl/Shift-клик) тащится целиком.
- **Действия:** ↻ поворот и ✕ убрать — при наведении; клавиши Del и R работают по выделенному.
  Поворот применяется и при экспорте DWG и картинок (раньше только PDF).
- **Ширина** колонки задаётся разделителем (мышь или стрелки ← →) и хранится в
  `localStorage["docStudio.treeWidth"]`. Сетка миниатюр — `auto-fill minmax(96px,1fr)`.
- **Миниатюры** — растры 420 px, по одной на лист, строятся в фоновой очереди
  (`queueThumbs`). Тормоза были оттого, что `<img>` каждой карточки был полный SVG листа в
  несколько МБ, и каждая перерисовка декодировала их все заново.
- Под миниатюрой одна тонкая строка — номер страницы в PDF этого документа.

## Paper space на холсте (23.09.2026)

`dwg_to_svg` выводит на холст **только** `*Model_Space`. Остальные записи, включая листы,
уходят в `<defs>` определениями, которые никто не использует. Поэтому рамка, штамп и надписи
листа не печатались, были видны только видовые экраны: у FEWA PIPING-066 из 148 объектов листа
не рисовался ни один. `isolate()` для листа на время вызова отдаёт его объекты записи
`*Model_Space`. Координаты при этом не меняются, это координаты бумаги в любом случае.

## Свой рендерер DWG → SVG (`dwg-render.js`, r2, 23.09.2026)

`dwg_to_svg` LibreDWG больше не используется, он остался только запасным путём (`parseLegacy`).
Рисуем сами из базы `convert()`, как печатает AutoCAD. Сверено с PDF, выведенными из AutoCAD:
C107 совпадает по положению до 0,1 мм, у FEWA A1 и C204 совпадают вид и цвета.

- **Цвет:**
  - ACI: 7 даёт чёрный на бумаге;
  - 24-битный цвет берётся из поля `color`, если оно не 0 и `colorIndex` не 256/0;
  - ByLayer и ByBlock;
  - объекты слоя «0» внутри блока наследуют слой вставки.
- **Вес линии** — индекс DWG (29 = ByLayer, 30 = ByBlock, 31 = Default, таблица 0–23 в сотых
  мм, LWDEFAULT). Ширина пишется в локальных единицах: мм / (мм бумаги на единицу).
- **Тип линии** — LTYPE × LTSCALE × масштаб объекта × PSLTSCALE. Если на бумаге период
  меньше 0,6 мм, линия рисуется сплошной.
- **Текст:**
  - высота TrueType-текста: кегль = 1,338 × высота, по замеру эталонных PDF;
  - SHX-текст (osifont, кегль по высоте заглавных) обводится толщиной линии объекта, как у
    AutoCAD;
  - MTEXT: коды `\f \H \W \C \c \S \P \pxq`, перенос по `rectWidth`, интервал 5/3, привязка
    1…9, фон.
- **Штриховки:** SOLID, узоры по `definitionLines` с обрезкой по контуру. Если шаг линий на
  бумаге меньше 0,25 мм или штрихов больше 25 000, штриховка рисуется тоном: так было у
  KEYPLAN FEWA, где GRAVEL давал 6 млн штрихов.
- **Прочее:** WIPEOUT, SOLID, LEADER, MLINE, SPLINE, атрибуты INSERT (`attribs`), DIMENSION
  через блок `*D`.
- **Отсечение видовым экраном** — по габаритам объектов, с учётом блоков. C107 похудел с
  4,9 до 2,5 МБ.
- **Страница:** если лимиты совпадают со стандартным листом, начало листа ставится в 0,0.
  Если лимиты чуть отличаются от стандартного листа (FEWA 878×620), лист вписывается в A1.
- **OLE-вставки** (логотипы, Excel):
  - контейнер CFB разбирается по потокам (`readCfb`), из потока `\x02OlePres000` берутся по
    очереди DIB, затем WMF (WMFJS), затем EMF (EMFJS; оба из rtf.js, MIT);
  - DIB уменьшается до 1400 px и сохраняется в JPEG 0,9;
  - у таблицы Excel (Aux SLD) сетку и заливку ячеек WMFJS не рисует, текст есть.
- **В PDF** блоки раскрываются из `<use>` на месте. svg2pdf считал рамку формы у повёрнутого
  вложенного блока нулевой и обрезал его целиком: так пропадал компас C107.
- **Шрифты** встроены в сайт (`fonts/`, LICENSES.txt): Arimo, Tinos, Cousine, osifont. Они
  регистрируются в странице (FontFace) и встраиваются в PDF (jsPDF addFont) один раз на весь
  документ: все DWG-листы идут одним jsPDF (`sheetsPdf`).
- **Известное:**
  - ACAD_TABLE в DWG 2018 (AC1032): LibreDWG не декодирует объект (все поля 0), поэтому
    таблица пропускается; в AC1015 работает;
  - IMAGE — внешние файлы, в DWG их нет;
  - Excel-OLE без сетки;
  - размер PDF в 1,5–2 раза больше, чем у AutoCAD (C107: 2,5 МБ против 1,6; FEWA: 1,5
    против 2,0); оптимизация отдельно.

## Окно превью и листы из модели (23.09.2026, r2d → r2e → r2f 24.09)

**r2f (24.09.2026)**, после жалобы «тормозит, не привязывается к углам, не убирает лишнее».
- **Тормоза были при масштабе экрана Windows 125–150 %.** Замер при 1920×1080 и dpr 1.25:
  панорама модели Senan шла 9,4 с на 40 движений при p95 283 мс; стало 1,5 с при p95 17 мс.
  Что было и что сделано:
  - линия «1 px» при dpr 1.5 получала ширину 1,5 физ. px и теряла быстрый hairline-путь
    Skia. Тончайшие веса теперь 1 физический пиксель;
  - на модели при FIT ~35 мс JS на кадр (`inherit`, `fontOf`, GC). Стили, шрифты и заливки
    разрешаются при компиляции (`paintOf`, runs с готовой строкой шрифта), состояние canvas
    не ставится повторно (`S`), bbox проверяется без аллокаций. Кадр 20 мс;
  - обзорный кэш `overview()`: лист целиком в растре до 4096 px. Он строится через 300 мс
    после первого чёткого кадра. Пока вид движется и зум не глубже его разрешения (×1,25),
    кадр — `blit()` за ~1 мс;
  - два canvas: во время движения рисуется низкий (1 px на CSS px), через 150 мс после
    остановки — полный. Размеры буферов не меняются, поэтому ничего не выделяется заново;
  - остались единичные кадры 150–250 мс: полная перерисовка после остановки.
- **Привязка к вершинам** (SNAP, F3, по умолчанию включена). `snapIndex(scene)` собирает
  концы отрезков и дуг, вершины полилиний, углы rect и картинок, центры окружностей
  (`pts` у каждого `p`-узла; при склейке штрихов они объединяются). Всё в единицах
  страницы, в сетке 512 с CSR. `snap(idx,x,y,r)` берёт ближайшую вершину в радиусе
  12 px экрана; зелёный квадрат `.snap-mark` — маркер. Проверено: мышь в 5 px от вершины
  → маркер и угол окна ровно в вершине.
- **Лист из окна обрезается по окну.** `makeSheet` оборачивает тело в `clipPath` с
  прямоугольником окна. Раньше объекты, задевшие окно, рисовались целиком и вылезали за
  контур.
- `?dsdebug=1` отдаёт `window.__ds = {view, host, commit}` для скриптов замера.


r2c (CSS-трансформация всего листа) пользователь отверг: тормозило, при зуме линии
толстели, картинка растровая. В r2d сделан векторный вьюпорт.

- **r2e — лист DWG рисуется на canvas** (`canvas-view.js`, `sceneHost`). r2d с SVG в DOM
  пользователь назвал «очень тормозит». Замер в headless Chrome на реальном GPU (Iris Xe),
  Senan SLD, 30 щелчков колеса: r2d — 7–14 с, кадры p95 217–383 мс; r2e — 1,6 с (это
  накладные стенда), p95 17 мс (60 fps). Senan Layout_v2 (DWG 109 МБ) и C107 тоже p95 17 мс.
  - Причина тормозов SVG: при каждой смене `viewBox` Chrome заново раскладывает весь
    SVG-текст (перешейпинг на новом масштабе) и все фигуры с `non-scaling-stroke`,
    100–600 мс на шаг, в главном потоке. CSS-настройками не лечится.
  - `compile(svg)`: DOMParser → сцена из узлов `g` (transform, clip-path) / `u` (use,
    общий блок) / `p` (Path2D) / `t` (текст из runs) / `i` (картинка), у каждого bbox.
    Понимает только подмножество, которое пишет `dwg-render.js`; иначе `null` и откат на
    `svgHost` (SVG в DOM). Подряд идущие одинаковые штрихи склеиваются в один Path2D
    (`merge`, до 256), заливки не склеиваются (правила заполнения).
  - `draw`: отсечение по bbox в пикселях экрана (+ bbox клипа вьюпорта), блоки и тексты
    меньше 0,5 px пропускаются, текст ниже 1 px — полупрозрачная полоска, иначе `fillText`
    на 100 px со scale (мелкие размеры не округляются). `dswNN` → ширина
    max(1, NN/100×4) px экрана; геометрические ширины — в единицах чертежа.
  - Пунктир теперь в единицах чертежа, как в PDF-печати и в AutoCAD. В SVG с
    non-scaling-stroke он был экранным и при зуме мельчал.
  - Кадр рисуется на каждый шаг колеса через rAF. Если интервал кадров > 45 мс дважды
    подряд (тяжёлый лист на слабом GPU), остаток жеста двигает последний кадр
    CSS-трансформом, а вектор дорисовывается через 110 мс после остановки.
  - Расхождение с SVG-отрисовкой по пикселям ≤1,3% (сглаживание) на Senan, C107, C204,
    Aux, FEWA — все листы идут через canvas.
  - `?svgview=1` в адресе включает прежнее SVG-превью (для сравнения).
  - Замер: скрипты `scratchpad/perf/*.js` (Playwright из `nodus-newengine/node_modules`,
    `channel:'chrome'`); замеры в скрытой панели браузера Claude недостоверны (rAF стоит).
    Первые ~10 с после загрузки идёт фоновая генерация миниатюр — её не мерить как зум.
- **Прежний SVG-вьюпорт (r2d, теперь откат)** (`view={s,x,y,cs,cx,cy,fit,pageId}`, `host`):
  - SVG заполняет окно (`preserveAspectRatio="none"`), зум и панорама меняют только
    `viewBox` (`draw`); белая бумага — вставленный `rect`;
  - во время жеста — лёгкий CSS-transform относительно последнего кадра
    (`liveTransform`), через 110 мс `commit()` перерисовывает `viewBox`, transform
    снимается, когда кадр готов;
  - PDF-страницы и картинки рисуются в canvas (`canvasHost`) только видимой областью
    (pdf.js viewport со смещением), поэтому резкость на любом зуме;
  - колесо (`passive:false`) зумит к точке под курсором (`zoomAt`, пределы fit×0,2…fit×400);
  - левая или средняя кнопка двигает, двойной клик/FIT вписывает, −/+ зумят к центру.
- **Экранные толщины** — фиксированные пиксели, как в AutoCAD, от зума не зависят:
  `.dswNN{vector-effect:non-scaling-stroke;stroke-width:max(1, NN/100×4)px}`. В печати
  экранный стиль убирается, там толщины в мм.
- **SHEET BY 2 CORNERS** (`setFraming`, `addSheet`, `modelPageOf`):
  - кнопка видна на любом листе DWG, у которого есть Model Space. С листа layout клик
    сначала открывает Model и включает режим. В r2d кнопка была только на Model, а та
    лежит в «NOT IN THE PDF», и пользователь её не нашёл;
  - два клика по углам (или протяжка), резиновая рамка `.frame-box`, Esc выходит;
  - координаты `viewBox` → чертёж: y меняет знак (`minY = -max(a.y,b.y)`);
  - `layout.makeSheet(win, sheet)` рендерит модель в окне на масштаб выбранного A0–A4
    (ориентация по рамке) и возвращает новый layout `model-sheet-N`;
  - новая страница встаёт после Model или после предыдущих вырезанных листов, режим
    остаётся включённым для следующего листа;
  - проверено на Senan: окно → «Model sheet 1», в PDF 420×297 мм (A3), вектор, текст есть.
- **Порядок отрисовки (SORTENTSTABLE, тип 714)** читается напрямую из LibreDWG
  (`readDrawOrder`), и записи блоков сортируются по ключу. У Senan белые заливки символов
  выключателей закрывали их собственные линии.
- **MTEXT:** `\C256` означает цвет слоя, `\C0` — цвет блока. У Senan «0,5S» с цветом объекта
  «красный» и кодом `\C256` на чёрном слое 0 должны быть чёрными. Хвостовые пробелы строк при
  выравнивании не учитываются, как в AutoCAD.
- **Шрифты:**
  - пятое семейство `dsgothic` = URW Gothic (AGPL + font exception), метрики Century
    Gothic / ITC Avant Garde; совпадение ширин 1:1 проверено на строке «33/√3»;
  - у прочих TTF подставляется ширина оригинала (`WIDTH`: Tahoma 0,966, Calibri 0,878,
    Verdana 1,106 и т.д.);
  - ISOCPEUR идёт в osifont.
- **Растр (IMAGE)** в Senan LibreDWG не декодирует (объектов типа 647 нет, есть только
  IMAGEDEF), а сами файлы внешние. Не рисуется.

## Экспорт DWG в PDF — вектор (23.09.2026)

Раньше в PDF шёл растр листа 4000 px, растянутый на A1. Выходило около 120 dpi, мыльные линии
и нечитаемый мелкий текст. Теперь `sheetPdf(layout)` в движке делает векторную страницу, а
pdf-lib копирует её в итоговый документ:

- **svg2pdf.js 2.8.1 + jsPDF 3.0.3** (MIT, jsDelivr) грузятся лениво при первом экспорте.
  Работают в браузере, без сервиса и лимитов.
- **Формат** — размер самого листа по лимитам LAYOUT, в мм: A4 выходит 297×210, A1 —
  878×620 вместе с полями. Лист меньше 60 единиц считается заданным в дюймах. Model без
  бумаги вписывается в A1 в своей ориентации.
- **Толщина линий.** На экране остаются LibreDWG-шные 0,1 % вида. В печати `printSvg` ставит
  одну толщину `PRINT_LW` = 0,18 мм на бумаге. В видовом экране она делится на его масштаб
  (`data-ds-scale` на группе). Индивидуальных lineweight библиотека не даёт.
- **Текст** заливается, без обводки. LibreDWG ставит `stroke` цвета объекта на группу, текст
  его наследовал, и буквы обводились линией чертежа, отсюда кляксы. Шрифт — Arial/Helvetica.
- **MTEXT (`setMText`).** LibreDWG не переносит MTEXT по ширине рамки (`rectWidth`) и ставит
  первую базовую линию на точку вставки. Группа `<g id="handle">` пересобирается:
  - перенос слов по замеру шрифта в canvas;
  - интервал 5/3·h·lineSpacing;
  - привязка attachmentPoint 1…9;
  - поворот по direction.
- Растр листа кэшируется в `vectorPdf` оригинала страницы, поэтому объединённые документы его
  переиспользуют. Лист A1 собирается около 2 с, файл весит около 2 МБ.

## Лишние определения блоков (`pruneDefs`)

LibreDWG пишет в `<defs>` все блоки чертежа. У PIPING-066 511 из 790 определений (74 % SVG на
6 МБ) не использовались. `pruneDefs` линейным проходом по тегам, без DOM, оставляет только
определения, до которых доходит `href="#…"` или `url(#…)` снаружи `<defs>`, в том числе через
другие блоки. Итог: листы 6,0 → 1,6 МБ (PIPING-066), 4,8 → 2,2 МБ (C107). `meta()` читает
размер из корневого тега регэкспом (раньше DOMParser всего листа, ~0,25 с на лист).

## Ограничения (известные)

- Заморозка слоёв по видовым экранам не поддерживается: библиотека не отдаёт `frozenLayerIds`.
- Клип видового экрана только прямоугольный; полигональные VP рисуются по своему прямоугольнику.
- Перспективные виды и 3D-виды (не план) не пересчитываются.
- На больших файлах parse занимает 2–10 с: основное время уходит в `dwg_to_svg`, по вызову на
  каждое пространство. Всё это время WASM идёт в главном потоке, и страница на время разбора
  замирает. Следующий шаг — вынести `dwg_read_data` / `convert` / `dwg_to_svg` в Web Worker
  (`drawnBox` и растры остаются в DOM).
- Word зависит от `api.ieccalc.com`: на 23.09.2026 он отдаёт 500.
