# #005 Engineering Document Studio — как устроен DWG-движок и страница

Доко-файл модуля `lab/document-studio/`. Страница собирает из DWG / PDF / картинок один PDF
в браузере. Файлы на сервер не уходят; исключение — Word, который идёт на конвертацию в
`api.ieccalc.com`. `ARCHITECTURE.md` рядом — старое описание замысла, по коду не актуально.

## Файлы

| файл | что делает |
|------|------------|
| `index.html` | страница: панель инструментов с дроп-зоной, три колонки (файлы → листы → превью), лента страниц PDF, экспорт |
| `libredwg-engine.js` | DWG → SVG-листы: `parseDwg(file)` и `svgToPng(svg)` |
| `libredwg-web.wasm` | не в git. CI (`.github/workflows/deploy-lab-pages.yml`) ставит `@mlightcad/libredwg-web@0.7.14` и кладёт WASM рядом при каждом деплое |

Импорт движка в `index.html` идёт с ключом кэша `?v=wasmN`. **Любая правка движка — бампать N.**

## Выкладка

Выкладка идёт через push в `main` репозитория `buchinskiievg/engineers_apps`, дальше GitHub
Actions запускает `wrangler pages deploy`. Работа ведётся в отдельном worktree. Коммит
fast-forward'ится в клон GitHub Desktop, и пользователь жмёт Fetch → Push.

## Модель данных libredwg-web 0.7.14 (то, что читает движок)

- Пространства: `db.tables.BLOCK_RECORD.entries`, `*Model_Space` / `*Paper_Space*`. Регистр в
  именах бывает любой: встречается `*MODEL_SPACE`.
- Объекты: `db.entities` — плоский список, у каждого `ownerBlockRecordSoftId`.
- Листы: `db.objects.LAYOUT` — `layoutName`, `tabOrder`, `minLimit/maxLimit` (лист бумаги),
  `viewportId` (handle собственного VP листа).
- Слои: `db.tables.LAYER.entries` — `frozen`, `off`, `plotFlag` (0 значит «не печатать»;
  у `Defpoints` всегда 0).
- VIEWPORT:
  - `viewportCenter`, `width`, `height` — на бумаге;
  - `targetPoint + displayCenter` — центр вида в модели;
  - `viewHeight` — высота вида в модели;
  - `viewTwistAngle` — поворот, радианы;
  - `statusBitFlags & 0x20000` — VP выключен;
  - `viewportId === 1` — сам лист.
- `frozenLayerIds` не заполняется, поэтому заморозку слоёв по видовым экранам сделать нельзя.

## Как рисуется DWG (`parseDwg`)

1. На каждый файл создаётся свой экземпляр `LibreDwg.create()`. Общий экземпляр ломается на
   втором чтении («null function» → Aborted). WASM отдаётся с ETag, так что повторная загрузка
   стоит около 0,5 с.
2. **Слои.** Объекты на слоях off / frozen / no-plot в лист не идут: `layerFilter`.
3. **Изоляция пространства.** `dwg_to_svg` рисует все блок-записи сразу, включая чужие
   пространства. `isolate()` опустошает остальные Model/Paper записи и оставляет только свои
   объекты.
4. **Модель рисуется один раз.** Она служит и отдельным листом «Model», и содержимым всех
   видовых экранов.
5. **Лист = бумага + окна в модель (`composeSheet`).** Paper space сам по себе — это штамп,
   рамки и прямоугольники VP, а внутри VP пусто. Лист из одних видовых экранов поэтому выходил
   пустым: так и было у пользователя, 23.09.2026. Для каждого VP модель вставляется
   клипованной группой:
   ```
   M = targetPoint + displayCenter,  s = height / viewHeight,  C = viewportCenter
   translate(Cx, −Cy) scale(s) rotate(twist°) translate(−Mx, My)
   ```
   Модель кладётся под графику бумаги, чтобы штамп лежал сверху. Id модели получают префикс
   `dsN-`: `<use>` берёт первый элемент с id, а в листе под теми же id лежат опустошённые копии.
6. **Рамка листа (`sheetExtents`).** Сначала лимиты LAYOUT (лист бумаги). Если их нет —
   extents листа. Если нет и их — объекты + прямоугольники VP.
7. **Рамка модели.** Пересечение двух коробок:
   - робастной по точкам (0,5–99,5 перцентиль; EXTMIN/EXTMAX из заголовка берутся, только если
     внутри ≥90 % точек и заголовок не больше 3× робастной);
   - реально нарисованной (`drawnBox`: `getBBox()` в скрытом DOM).

   Одних точек мало: INSERT считается по точке вставки, и блок с базой в начале координат
   растягивал рамку. C107 шириной 80 единиц выходил в рамке 1 300, с чертежом-точкой в углу.
8. Листы, в которых нечего показать, помечаются `empty`. Если все листы пустые, а модель нет
   (`modelOnly`), модель включается сама.

### Очистка SVG от LibreDWG

- **Экранирование текста (`xmlSafe`).** Текст чертежа пишется как есть: «Bopp & Reuther»,
  «R<=2 Ohm». Это невалидный XML. Инлайн в странице он прощается, а в `<img>` не грузится. Все
  миниатюры и растр для PDF были пустыми практически на любом реальном чертеже. Движок
  экранирует содержимое `<text>` (`<tspan>` библиотека не пишет) и голые `&`, выбрасывает
  запрещённые управляющие символы.
- **Цвет 7 (`onPaper`).** LibreDWG пишет его белым, AutoCAD печатает чёрным. Белый заменяется
  на чёрный — это второй по частоте цвет на всех тестовых чертежах.
- **Корень `<svg>` пересобирается (`frame`).** Второй `preserveAspectRatio` или `width` тоже
  делает XML невалидным.
- **ACAD_TABLE роняет `dwg_to_svg`** («topBorderVisibility»). `drawSvg` повторяет отрисовку без
  таблиц и сообщает, сколько пропущено.

## Колонка «Pages / Layouts»

Под миниатюрой одна тонкая строка (15 px) с **номером страницы в итоговом PDF**. Это позиция в
`state.pages` + 1: DWG-лист ищется по `layout.id`, PDF-страница — по `id`. Лист, не попавший
в PDF, показывается бледным и с «—». Имя листа выводится во всплывающей подсказке. Крупные
подписи и бейдж порядкового номера убраны по просьбе пользователя 23.09.2026.

## Ограничения (известные)

- Заморозка слоёв по видовым экранам не поддерживается: библиотека не отдаёт `frozenLayerIds`.
- Клип видового экрана только прямоугольный; полигональные VP рисуются по своему прямоугольнику.
- Перспективные виды и 3D-виды (не план) не пересчитываются.
- На больших файлах parse занимает 2–10 с: основное время уходит в `dwg_to_svg`, по вызову на
  каждое пространство.
- Word зависит от `api.ieccalc.com`: на 23.09.2026 он отдаёт 500.

## Проверка

- Локально: сервер `py -m http.server` в корне worktree, в консоли
  `import('/lab/document-studio/libredwg-engine.js')`, затем `parseDwg` по файлам.
- Критерии:
  - каждый `previewUrl` грузится в `<img>`;
  - листы из одних VP не пустые;
  - `svgToPng` даёт ненулевую «заливку».
- Публичные тестовые DWG:
  `raw.githubusercontent.com/LibreDWG/libredwg/master/test/test-data/example_{2000,2007,2013,2018}.dwg`.
  В них модель и пустые листы.
- Клиентские DWG на прод не грузить и в git не коммитить.
